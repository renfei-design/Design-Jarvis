# Governance

Design Jarvis is maintained as a community-oriented, vendor-neutral open-source project.

## Maintainers

Maintainers are contributors with repository write access who review changes, protect releases, enforce community standards, and keep the public core broadly reusable. New maintainers should demonstrate sustained, constructive contributions and sound judgment across product quality, security, and community health.

## Decisions

- Routine changes are decided through review and automated checks.
- Material changes to agent boundaries, artifact contracts, memory schemas, security posture, licensing, or supported integrations require an explicit rationale and maintainer review.
- When maintainers disagree, prefer reversible experiments and documented evidence. The project’s vendor-neutral principles and user safety take priority over organization-specific convenience.
- Conflicts of interest must be disclosed and the affected maintainer should recuse themselves when appropriate.

## Releases

Releases use semantic versioning where practical, include human-readable notes, pass the repository verification suite, and are built from reviewed source. Release artifacts should be reproducible from a tagged commit and distributed through channels controlled by the project maintainers.

## Project scope

Organization-specific connectors, proprietary design systems, private knowledge, and internal governance belong in separate packs or forks. Proposals that make the public core depend on them will not be accepted.
